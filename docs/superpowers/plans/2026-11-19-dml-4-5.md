# DML-4: Resume saved daily recommendations and cross-day drafts

### What to build

Open Today to a saved, varied pair of questions, choose extra or focused practice, and resume drafts safely across refreshes, tabs and days.

### Acceptance criteria

- [ ] Atomically save each local date’s recommendation pair and immutable question/rubric/source snapshots before display. Refresh, restart and simultaneous tabs return the same saved pair.
- [ ] Select one random eligible due review when available and one varied question favouring less recently practised sections, from a different section/concept when possible. With no due review, select two varied questions. Inject randomness for repeatable tests.
- [ ] Offer more questions and section-focused practice; save extras on demand. Prefer questions not practised that day, avoid duplicate question IDs in the pair and resume an existing unfinished item. Explain shortages while retaining the goal of two.
- [ ] Save drafts explicitly and before in-app question navigation, showing saved status only after SQLite acknowledgement. A failed save preserves editor text and offers retry/copy; closing with unsaved edits uses the browser’s native warning.
- [ ] Use conditional draft versions so an older tab cannot silently overwrite a newer saved draft. Show both the local text and the saved alternative on conflict.
- [ ] Keep unfinished work editable after midnight, with its original snapshot; prepare today’s pair without hiding resumed work. Question selection and draft saving work offline and before sign-in.
- [ ] Enforce the configured 8,000-Unicode-code-point limit consistently in Python and React; 8,001 is rejected without truncation or loss of local text.
- [ ] Complete the MagicPath Today proportions/tokens and responsive session selector. Keep extra/section actions reachable at small widths; preserve focus, skip link, visible labels, text statuses, 44px controls and reduced-motion/transparency support.

### Verification

Pytest for saved selection, two-connection races, immutable snapshots, deterministic variety, extras/resumption and draft conflicts; UI save/failure/navigation checks; compare 1440/1024/768/390px and 200% zoom with the pinned reference.

## Task 2: DML-5

# DML-5: Submit answers, receive feedback and earn calendar credit safely

### What to build

Submit a real practice answer, see concise feedback when grading succeeds, and keep both the answer and its daily credit when grading is pending or fails.

### Acceptance criteria

- [ ] Validate the answer and atomically save immutable original text, completion date/timezone, one calendar credit and a logical grading request before any network send. One original per practice item and one credit per question/local completion date hold even with different concurrent action keys.
- [ ] Show actual calendar counts: 0 no practice, 1 partial, 2+ goal met, including counts above two. Leave future/pre-first-use dates unmarked and identify today’s zero as no practice yet; include accessible text/date labels.
- [ ] Credit resumed/focused/recommended answers on the date they are finished using the effective learning timezone at commit. Later grading, disputes, retries or clarification/revision never move or duplicate that credit.
- [ ] Present grade, understood points, specific corrections and a concise model answer first, with expandable reasoning/example/sources and an AI-generated-feedback label. Reopening stored feedback makes no provider call.
- [ ] Expose distinct awaiting_access, awaiting_allowance, queued, in_flight, needs_clarification, outcome_unknown, failed_recoverable and assessed states. Preserve answer/credit through sign-in, plan-limit, timeout, refusal, invalid-output and interrupted-stream failures.
- [ ] On restart, distinguish unsent queued work from interrupted/uncertain sends. Offer explicit later send/retry for unavailable access, plan limits and uncertain outcomes; explain possible prior usage for uncertain sends.
- [ ] Claim/finalize requests once with short transactions; release database transactions during network calls. A confirmed transient 429 may receive at most one bounded retry when Retry-After is at most 5 seconds; uncertain sends are not silently repeated.
- [ ] Keep navigation and other practice usable while a question is grading, with polling limited to active requests. Persist feedback and its available learning evidence atomically so ticket 6 can derive schedules from existing assessments.

### Verification

Targeted pytest for submissions, calendar dates/deduplication, provider/restart recovery and request counts; browser journey including refresh/two tabs and a tab left open overnight; Europe/London DST boundary coverage and frontend checks.

### Constraints and traceability

This ticket counts original submitted answers. Explanation-view completion for “I don’t know” is added in ticket 7. Drafts and all follow-on actions on an answer add no calendar credit.

Specification coverage: AC04, AC08, AC09, AC10, AC11, AC15, AC21, AC22. Apply the shared scope and implementation standards above.
