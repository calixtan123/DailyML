# DML-1 ChatGPT OAuth references

Checked on 17 November 2026.

- Initial authorization uses the dynamic entrypoint with the app name and a stable UUID host URN. Returning sign-in uses the issued client. The loopback callback keeps the scheme, address and path fixed, and code exchange repeats the actual callback URI and PKCE verifier. [Registration and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in.md), [Host identity](https://developers.openai.com/siwc/token-sharing-open-source.md)
- The provider metadata advertises RS256, the issuer, signing keys and the public-client token and revocation endpoints. Python verifies the signed ID token and compares the existing registration before saving replacements. The exchange response supplies the plan grant. [OpenID discovery](https://auth.openai.com/.well-known/openid-configuration), [Identity validation](https://developers.openai.com/siwc/website.md)
- Refresh uses the saved issued client and resource. It omits scope and replaces the complete token set atomically. Retryable failures preserve the local session. Confirmed terminal refresh failures remove tokens and retain the registration. Sign-out attempts revocation using the latest refresh token and shows whether revocation was confirmed. [Accounts and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions.md), [Errors and recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery.md), [Token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference.md)
- Future grading must use the documented Responses HTTP preview contract, including `store=false`, `stream=true` and array input, with the unsupported fields omitted. DML-1 makes zero model requests. [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations.md)
- The Settings page uses the documented sign-in label and links to official usage, credit, privacy and connection controls. [UI guidelines](https://developers.openai.com/siwc/ui-ux-guidelines.md), [Plan usage and credit controls](https://help.openai.com/en/articles/20001542-using-your-chatgpt-plan-in-other-apps-and-sites), [Data controls](https://help.openai.com/en/articles/7730893-data-controls-in-chatgpt)

DML-1 handles one verified registration per installation. The optional account hints stay out of browser URLs. A protected record retains the subject, display email, issued client and validated ID token while the session is active. Real-account eligibility, renewed consent and provider interoperability still require the learner's manual sign-in. The installed and browser tests use an isolated data directory and simulated authorization.

A state-checked decline of a returning authorization leaves existing tokens in place and enables an explicit consent retry with the full scope and `prompt=consent`. A confirmed token-endpoint `invalid_client` takes a separate recovery path. The next deliberate sign-in requests a new registration with the stable host ID, and the app replaces the old registration only after verifying the original subject, the new audience and the plan grant. The provider documents fixing the client configuration; dynamic replacement is this app's recovery choice and awaits live verification. [Errors and recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery.md)

OAuth network requests run in a disposable Python process. The backend controls the total deadline across the token exchange and signing-key request, stops and reaps an in-flight process on cancellation, and owns all credential validation and writes.
